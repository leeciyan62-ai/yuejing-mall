# 悦境商场数字导览产品文档

版本 1.0 · 2026 年 10 月 19 日

悦境 MALL 是面向万达、银泰等商业综合体使用场景的数字导览概念原型。它将传统楼层索引转化为可探索的三维店铺场景，帮助消费者发现店铺、规划消费，同时向商场运营团队演示可量化的互动触点。悦境为虚构商场，本项目不代表与任何商场或品牌存在合作。

## 产品定位

核心任务是让用户在一分钟内回答三个问题：这层有什么、哪家值得去、我准备体验什么。首页以场景探索为主，店铺目录作为可检索、可键盘操作的并行入口。

原型以商场的轻量数字触点为定位，可用于招商演示、品牌活动提案和数字导览体验验证。正式落地可放在商场公众号、H5 链接、现场二维码和导览屏入口；这些渠道目前没有接入。

## 关键体验流程

1. 进入首页，看到 B1 场景和本层六家店铺。
2. 使用楼层按钮切换，或打开整栋总览点击楼板进入。
3. 拖动旋转模型，滚轮或双指缩放；点击走廊让小人移动。
4. 点击场景中的店铺或列表卡片打开店铺详情。
5. 查看铺位、品类、推荐体验和参考价格，将喜欢的内容加入清单。
6. 在清单中调整数量或删除，查看预计总价。
7. 生成游逛小票，查看已探索店铺数、到访楼层数和预计消费，导出 PNG 图片。

搜索覆盖全部三十家店铺，支持店名、品类和商品名称；搜索结果进入其他楼层时同步切换场景。空结果提供示例搜索词。清单为空时仍可生成零消费的探索纪念小票。

## 本版功能范围

| 功能 | 行为与边界 |
| --- | --- |
| 三维导览 | 五层程序化场景；整栋堆叠总览与单层查看；轨道旋转与缩放 |
| 店铺定位 | 选中店铺出现地面标记，小人走向对应走廊位置；不是室内导航 |
| 店铺详情 | 每店一项代表商品或体验，统一营业时间展示 |
| 消费清单 | 本机保存，支持数量 1 至 99；数量减至零移除；可清空 |
| 分享图片 | Canvas 生成 PNG；使用浏览器下载，不发送至社交平台 |
| 运营概览 | 本机详情浏览次数、详情页加购次数、店铺排名和楼层覆盖 |
| 服务设施 | 客梯示意、洗手间与母婴服务概念配置；部分设施仅文字展示 |
| 响应式 | 桌面左右分栏，窄屏场景在上、目录在下 |

本版不含真实订单、支付、预约、排队叫号、会员登录、优惠券、库存、停车寻车、室内定位、多租户管理后台或远程埋点。运营概览不是线上管理系统。

## 产品设计原则

三维场景负责激发兴趣，目录负责高效完成任务。任何店铺都能通过列表访问，不强迫用户理解三维操作。

将楼层标题、店铺主题色、陈设类型和文案形成一致识别。浅色建筑模型与温暖中性色适合品牌提案，避免画面过暗影响招牌辨识。

清单使用“预计消费”，而不使用“订单”或“支付”。餐厅商品是体验套餐示意，不承诺可售库存和实时席位。

## 运营指标定义

本版只保存当前浏览器数据，用于演示口径，不用于评估真实商场经营效果。

- 详情浏览次数：每次打开店铺详情累计一次，包括重复打开。
- 已探索店铺：按店铺 ID 去重。
- 详情页加购次数：点击详情中的加入按钮成功时累计；清单中增加数量不计入该指标。
- 楼层覆盖：该层去重探索店铺数除以六。
- 预计消费：当前清单中参考单价乘数量之和，不是成交金额。

正式版本建议建立会话级漏斗：进入导览、搜索、查看店铺、领取权益、到店核销。需要分别定义曝光有效时长、会话去重、测试流量过滤和授权的数据保留周期，不把浏览行为解释为到店或交易。

## 正式落地所需输入

商业方需提供楼层平面图、铺位 ID、店铺清单、品牌授权资料、真实营业时间、服务设施点位及更新责任人。店铺详情上线前应由商户或商管审核。接入优惠券和会员后，应明确第三方服务、身份关联、撤回和数据保留机制。

导航功能需要可通行区域、通道连接、电梯和扶梯连接关系，并以无障碍路线作为独立能力验证。当前简化走廊模型不能直接用于真实路线指引。

## 迭代路径

第一阶段验证消费者是否能找到目标店铺、是否愿意浏览其他楼层、分享小票是否有传播价值。可用现场观察与可用性访谈收集反馈。

第二阶段接入真实商场内容管理、品牌图片、营业状态和活动配置，保留当前数据驱动场景接口；同步开展目标手机和商场导览屏性能测试。

第三阶段按商业目标接入会员、权益核销、预约或导航。每项能力独立定义服务承诺和失败反馈，避免演示界面被误认为已连接业务系统。

## 验收标准

五个楼层均可访问且目录与场景一致；三十家店铺均能打开详情；搜索跨层有效且空状态明确；清单数量和总价正确；刷新后保留本机状态；小票图片包含与界面一致的汇总；窄屏可访问核心操作；三维初始化失败时保留目录与清单能力。
