# 悦境商场数字导览技术文档

版本 1.0 · 2026 年 10 月 19 日

本项目是原生 ES Module 与 Three.js 驱动的本地静态原型。五层商场和三十家店铺由程序化几何体生成，业务数据由单一配置文件提供，浏览记录与清单保存在浏览器本地。没有构建流程，也没有业务服务端。

## 技术选型

| 层次 | 实现 |
| --- | --- |
| 页面 | HTML、CSS、原生 JavaScript |
| 三维 | Three.js r180。自定义三渲二 shader、反壳描边、招牌图集、暖光与蒸汽 |
| 资源加载 | import map 映射到 vendor/three.module.js，内部加载 three.core.js |
| 建模 | Box、Cylinder、Sphere、Torus、Plane、Ring 基础几何体 |
| 招牌 | Canvas 2D 绘字，CanvasTexture 映射到平面 |
| 动画 | setAnimationLoop、时间步长、小人肢体正弦摆动、相机指数插值 |
| 选择 | Raycaster 读取 Mesh 上的 shop 或 floor 标识 |
| 存储 | localStorage，键 yuejing-mall-v1 |
| 图片导出 | Canvas 2D、toBlob、Object URL、下载链接 |
| 本地服务 | Node.js 内置 http 与 fs，无服务端依赖 |

Three.js 官方 r180 构建文件随项目保存，保留 MIT 许可证。首次下载通过官方 GitHub 仓库完成。启动不需要 npm install，也不需要 CDN。

## 数据结构

FLOORS 包含 id、主题名称、英文标题、描述、主题色和 shops。每店有唯一 id、floor、index、name、category、kind、product、price、slogan 和 unit。价格以整数人民币元存储，当前商品没有小数价格；真实交易系统应改为分并由服务端校验。

店铺 id 由楼层与本层序号构成，示例 B1-1。各层固定六店，按两排三列布置。添加第七家店或改变布局时需要同时修改 scene.js 的定位逻辑，不能只增加配置。

浏览器状态包含 bag、visited、views、adds。bag 只存店铺 ID 和数量，名称与价格从静态配置解析，防止存储残留的旧展示字段与当前数据不一致。读取时过滤未知 ID 和不合法数量，数量上限 99。后续接入动态数据时还需增加完整 schema 校验和迁移策略。

## 程序化建模

每层是一个 Three.Group，层高间距 4.6。底板 28 × 21，六个店铺各约 7.7 × 5.6，中间为可行走通道。切换楼层仅显示当前 Group，整栋模式显示所有楼层。

店铺先构建底板、后墙、侧墙、边柱、招牌和植物，再根据 kind 生成陈设：

- 麻辣烫与面食：柜台、小锅、餐桌、商品架。
- 奶茶与咖啡：圆柱杯体、细吸管、柜台与座位。
- 珠宝与眼镜：展示底座、半透明玻璃罩、圆环饰品；眼镜由两个圆环和鼻梁拼接。
- 服装与运动：支杆衣架、多色衣片、展示台。
- 电影院：屏幕、三排六列座椅。
- 健身：跑步机底板、扶杆和控制屏。
- 儿童：彩色积木和圆柱、球体组合玩具。
- 瑜伽：垫子与球体。
- 餐厅：桌面、桌腿、椅子和餐具，火锅店增加锅体和汤面。

招牌在离屏 Canvas 绘制，再作为纹理贴到平面上。系统字体保证中文可用，具体字形可能随系统改变。没有外部模型、照片、HDR 环境图或动画文件。

主角由方块身体、腿、头发和球形头部组成。行走用正弦摆腿，旋转朝向目标点；目标限定在中心通道，无导航网格、物理引擎、碰撞避障或跨层路径计算。

## 交互与相机

屏幕坐标经画布边界归一化后交给 Raycaster。单层优先检测店铺网格，点击任意陈设均打开对应详情；未命中店铺时与当前楼层水平面求交，把目标点限制在走廊范围。整栋模式只拾取楼板。

Pointer Events 统一鼠标与触摸。单指拖动调整 yaw 和 pitch，双指距离调整镜头距离，滚轮调整缩放。拖动距离超过阈值后禁止同一手势触发店铺点击。

相机围绕当前楼层中心旋转，使用指数平滑消除突跳。楼层目录是三维操作的等价入口。当前未实现 WASD、第一人称视角、实际电梯乘坐或店内自由走动。

## 性能与限制

共享基础几何体和同色材质，限制设备像素比至 1.6；单层模式隐藏其他楼层。未开启实时阴影、后处理或物理碰撞。

当前为可读性优先的原型，没有按材质合并静态网格，也没有 InstancedMesh 批量化。整栋模式同时显示三十店，绘制调用明显高于单层。正式上线需测量目标设备上的 draw call、GPU 帧时间和内存，再进行合批、按层懒加载、招牌图集和动态分辨率优化。不能引用参考夜市项目的性能数据作为本项目实测。

每层静态模型按材质合并后走同一套三渲二：三段渐变、暖色受光、冷色阴影、边缘光、雾和反壳描边。招牌是灯箱图集，通道有灯串、地面暖光和餐饮蒸汽。建筑仍是概念布局，不是 CAD 精度数字孪生。

## 运行与部署

推荐 Node.js 22 或更新版本。在项目目录运行 npm run dev，打开 http://127.0.0.1:5173/。可用 PORT=5174 npm run dev 指定其他端口。npm run check 检查业务模块语法。

需要通过 HTTP 访问，不能直接双击 index.html 使用 file 协议加载 ES Modules。macOS 可使用根目录启动脚本。

静态上线时只需 index.html、src、vendor，保留资源相对路径。可以部署在静态 HTTP 服务或对象存储站点。本次没有公开发布。serve.mjs 只监听回环地址，用于开发，不用于生产互联网服务。

## 稳定性与安全边界

三维初始化错误会显示提示，目录与清单仍可操作。若引擎文件本身缺失或模块加载失败，入口脚本也无法正常初始化，因此 vendor 文件必须一起交付。

存储异常不会阻断本次操作，但无法保证跨刷新保存。浏览器清除站点数据会丢失记录。页面没有上传遥测、账户数据、支付信息或位置数据的接口。

业务界面目前从受控静态配置生成 HTML。正式接入 CMS 时必须转用 textContent、安全模板或进行严格转义，不能直接将外部文本拼接进 innerHTML。业务价格、权益核销和权限判断应迁移到服务端。

## 扩展设计

场景层保持 shopId 与数据分离；内容服务提供 store、floor、tenant、product 等实体。新增 CMS 时由 API 返回审核后的店铺资料；模型模板继续根据 kind 选择。更高精度店型可以用 GLB 替换单个程序化 Group，保留相同 shopId 拾取接口。

真实导航需引入可通行多边形、楼层连接图、起终点及无障碍约束。真实运营数据需建立事件版本、去重、会话、授权、保留和删除机制。后台应与消费者页面分开部署并做身份认证，不能将本机运营弹窗直接当成后台。
